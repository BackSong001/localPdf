# REQUIREMENT.md — 요구사항 명세

이 문서는 구현과 테스트의 기준(Single Source of Truth)입니다. 모든 요구사항은 **ID**, **인수 조건**, **테스트 ID**를 가지며, TDD는 테스트 ID 단위로 실패 테스트를 먼저 작성합니다.

- 범위: v1 = 이미지 → PDF 변환 + PDF 텍스트 추출
- v2 = LLM 요약 (별도 표기)
- 용어: **Job** = 한 번의 이미지 묶음 → PDF 변환 작업

---

## 1. 기능 요구사항 (Functional Requirements)

### FR-001 이미지 일괄 업로드

사용자는 jpg/jpeg/png/webp/bmp/tiff 이미지를 한 번에 최대 1,000장까지 업로드할 수 있다.

**인수 조건**
- Given 사용자가 지원 형식 이미지 N장(1 ≤ N ≤ 1,000)을 선택했을 때
- When 업로드를 실행하면
- Then 서버는 모든 파일을 임시 디렉터리에 저장하고 Job을 생성한다.

**거부 조건**
- 0장 → `EMPTY_UPLOAD`
- 1,001장 이상 → `TOO_MANY_FILES`
- 파일 1개 50 MiB 초과 → `FILE_TOO_LARGE`
- 전체 2 GiB 초과 → `TOTAL_SIZE_EXCEEDED`
- 지원하지 않는 형식/손상 파일 → `UNSUPPORTED_IMAGE` / `INVALID_IMAGE`

**테스트 ID**: `TC-FR-001-a`(정상), `TC-FR-001-b`(0장), `TC-FR-001-c`(개수 초과), `TC-FR-001-d`(용량 초과), `TC-FR-001-e`(형식/손상)

---

### FR-002 페이지 순서 보존

PDF 페이지 순서는 업로드된 파일 순서(= UI 표시 순서)와 일치해야 한다.

**인수 조건**
- Given UI에서 파일 순서를 `a.jpg, b.jpg, c.jpg`로 정했을 때
- When 변환이 완료되면
- Then PDF 1~3페이지는 각각 a, b, c 이미지다.

**세부 규칙**
- 최초 목록 정렬은 파일명 **자연 정렬**(`img2` < `img10`)이다.
- 사용자는 UI에서 순서 변경/삭제가 가능하다.
- 서버는 multipart 파트 수신 순서를 그대로 사용한다.

**테스트 ID**: `TC-FR-002-a`(자연 정렬), `TC-FR-002-b`(전달 순서 보존)

---

### FR-003 페이지 크기와 배치

각 이미지는 A4 페이지에 비율을 유지하며 배치된다.

**인수 조건**
- Given 이미지가 주어졌을 때
- When PDF를 생성하면
- Then 각 페이지는 A4(595.276 × 841.89 pt)이며, 이미지 방향에 따라 세로/가로가 자동 선택된다.
- Then 이미지는 잘리지 않고, 여백 0, 중앙 정렬, 비율 유지로 배치된다.

**세부 규칙**
- `가로 > 세로` 이미지 → 가로 A4(841.89 × 595.276 pt)
- 그 외(정방형 포함) → 세로 A4
- 스케일 = `min(page_w / img_w, page_h / img_h)` (업스케일 허용)
- 페이지 수 == 이미지 수

**테스트 ID**: `TC-FR-003-a`(세로), `TC-FR-003-b`(가로), `TC-FR-003-c`(정방형), `TC-FR-003-d`(페이지 수)

---

### FR-004 EXIF 방향 보정

EXIF Orientation이 있는 JPEG는 회전이 적용된 상태로 PDF에 들어간다.

**인수 조건**
- Given Orientation=6(90° 회전 필요) JPEG가 주어졌을 때
- When 변환하면
- Then PDF의 이미지 방향이 실제 보이는 방향과 일치한다.

**테스트 ID**: `TC-FR-004-a`

---

### FR-005 투명도 처리

알파 채널이 있는 이미지는 흰색 배경으로 평탄화된다.

**인수 조건**
- Given 투명 PNG가 주어졌을 때
- When 변환하면
- Then PDF에서 투명 영역은 흰색으로 보인다.

**테스트 ID**: `TC-FR-005-a`

---

### FR-006 변환 진행률

사용자는 변환 진행 상황을 확인할 수 있다.

**인수 조건**
- Given Job이 생성되었을 때
- When 프론트엔드가 500 ms 간격으로 상태를 조회하면
- Then `processed / total`이 단조 증가하고, 완료 시 `status=done`이 된다.

**세부 규칙**
- 서버 상태: `queued` → `converting` → `done` | `error`
- `processed`는 성공적으로 PDF에 추가된 이미지 수다.

**테스트 ID**: `TC-FR-006-a`(상태 전이), `TC-FR-006-b`(진행률 단조 증가)

---

### FR-007 PDF 다운로드

완료된 Job의 PDF를 다운로드할 수 있다.

**인수 조건**
- Given `status=done`인 Job에 대해
- When 다운로드를 요청하면
- Then `Content-Type: application/pdf`와 함께 파일이 반환된다.

**거부 조건**
- 존재하지 않는 Job → `JOB_NOT_FOUND`(404)
- 아직 완료되지 않은 Job → `JOB_NOT_READY`(409)

**테스트 ID**: `TC-FR-007-a`(정상), `TC-FR-007-b`(미완료), `TC-FR-007-c`(없는 Job)

---

### FR-008 PDF 텍스트 추출

사용자는 PDF를 업로드해 텍스트 레이어를 추출할 수 있다.

**인수 조건**
- Given 텍스트 레이어가 있는 PDF를 업로드했을 때
- When 추출을 요청하면
- Then 페이지별 텍스트와 전체 텍스트가 반환된다.

**세부 규칙**
- 각 페이지 텍스트는 앞뒤 공백을 제거한다.
- 전체 `text`는 **비어 있지 않은** 페이지 텍스트를 `"\n\n"`로 연결한 값이다. 모든 페이지가 비면 `""`다.
- `page_count`는 PDF 전체 페이지 수다.
- OCR은 수행하지 않는다.

**테스트 ID**: `TC-FR-008-a`(페이지별 일치), `TC-FR-008-b`(전체 텍스트 연결), `TC-FR-008-c`(페이지 수)

---

### FR-009 텍스트 없는 PDF 처리

텍스트 레이어가 없는 PDF(스캔 이미지 전용)는 오류가 아니라 빈 결과로 안내한다.

**인수 조건**
- Given 이미지로만 구성된 PDF를 업로드했을 때
- When 추출하면
- Then `has_text=false`, `text=""`, 모든 페이지 텍스트가 빈 문자열이다.

**테스트 ID**: `TC-FR-009-a`

---

### FR-010 추출 텍스트 활용

사용자는 추출 결과를 복사하거나 `.txt` 파일로 다운로드할 수 있다.

**인수 조건**
- Given 추출이 완료되었을 때
- When 복사/다운로드 버튼을 누르면
- Then 클립보드에 전체 텍스트가 복사되거나 UTF-8 `.txt`가 저장된다.

**테스트 ID**: `TC-FR-010-a`(복사), `TC-FR-010-b`(다운로드) — 프론트엔드 수동/컴포넌트 테스트

---

### FR-011 입력 검증

서버는 확장자가 아니라 실제 파일 내용으로 형식을 검증한다.

**인수 조건**
- Given 확장자만 이미지인 손상 파일이 주어졌을 때
- When 업로드하면
- Then `INVALID_IMAGE`(422)로 거부된다.
- Given PDF가 아닌 파일이 주어졌을 때
- When 텍스트 추출을 요청하면
- Then `UNSUPPORTED_PDF`(415)로 거부된다.

**테스트 ID**: `TC-FR-011-a`, `TC-FR-011-b`

---

### FR-012 임시 파일 정리

Job의 임시 산출물은 성공/실패/서버 종료 시 정리된다.

**인수 조건**
- Given Job이 완료되었거나 실패했을 때
- When 완료/실패 후 TTL(기본 1시간)이 지나거나 서버가 종료되면
- Then 해당 Job의 임시 디렉터리가 삭제된다.
- Then TTL 이후 상태 조회/다운로드는 `JOB_NOT_FOUND`(404)다.
- 진행 중(`queued`/`converting`) Job은 TTL 정리 대상이 아니다.
- 변환 실패 시 부분 `output.pdf`는 즉시 삭제하고, Job 상태/디렉터리는 TTL까지 유지한다.
- 업로드 검증 실패 시 생성된 임시 디렉터리는 즉시 삭제한다.

**테스트 ID**: `TC-FR-012-a`(완료 후 TTL 정리), `TC-FR-012-b`(실패 시 부분 산출물 정리), `TC-FR-012-c`(종료 시 정리), `TC-FR-012-d`(진행 중 제외), `TC-FR-012-e`(검증 실패 즉시 정리)

---

### FR-013 헬스체크

서버 상태를 확인할 수 있다.

**인수 조건**
- When `GET /api/health`를 호출하면
- Then `200`과 `{"status":"ok","version":"..."}`를 반환한다.

**테스트 ID**: `TC-FR-013-a`

### FR-014 로컬 전용 바인딩

서버는 기본적으로 `127.0.0.1`에만 바인딩된다.

**인수 조건**
- Given 기본 설정으로 실행하면
- Then 외부 인터페이스에서 접근할 수 없다.

**테스트 ID**: `TC-FR-014-a` — 실행 설정 검사(수동/스모크)

---

### FR-015 오류 메시지

모든 오류는 사용자가 이해할 수 있는 한국어 메시지와 안정적인 코드를 포함한다.

**인수 조건**
- Given 오류가 발생했을 때
- Then 응답은 `{"detail":{"code":"...","message":"..."}}` 형식이다.
- Then 내부 스택트레이스/파일 경로/비밀키는 노출되지 않는다.

**테스트 ID**: `TC-FR-015-a`

---

### FR-016 요약 (LLM)

추출된 텍스트 또는 Job의 텍스트를 무료 LLM API(Gemini 또는 NVIDIA NIM)로 요약한다.

**인수 조건**
- Given 텍스트 또는 완료된 Job이 있을 때
- When 요약을 요청하면
- Then Gemini 또는 NVIDIA NIM을 통해 요약문(`summary`), `provider`, `model`을 반환한다.
- Then API 키가 설정되지 않은 경우 400 `LLM_NOT_CONFIGURED`를 반환하고 설정 방법을 안내한다.
- Then 텍스트가 비어 있는 경우 400 `EMPTY_TEXT`를 반환한다.
- Then API 키는 `.env`에서만 읽고 로그/응답에 절대 노출하지 않는다.

**테스트 ID**: `TC-FR-016-a`(정상 요약), `TC-FR-016-b`(키 미설정), `TC-FR-016-c`(텍스트 없음)

---

### FR-017 RapidOCR 기반 Searchable PDF 및 Markdown 생성

이미지 변환 시 RapidOCR을 실행하여 투명 텍스트 레이어를 PDF에 주입하고, 전체 텍스트를 Markdown 파일로 함께 생성한다.

**인수 조건**
- Given 글자가 포함된 이미지를 변환 요청했을 때 (기본 `ocr=true`)
- When 변환이 완료되면
- Then 생성된 PDF 내부에 검색/복사 가능한 투명 텍스트 레이어(`render_mode=3`)가 삽입된다.
- Then Job 디렉터리에 `output.md` 파일이 함께 생성되고 `/api/jobs/{job_id}/markdown`으로 다운로드할 수 있다.
- Then Job snapshot에 `markdown_url`이 포함된다.

**테스트 ID**: `TC-FR-017-a`(투명 텍스트 레이어 삽입 확인), `TC-FR-017-b`(Markdown 파일 생성 및 다운로드), `TC-FR-017-c`(OCR 옵션 비활성화 시 기본 이미지 PDF 생성)

## 3. 제약 및 가정

- 단일 사용자, 로컬 실행, 인증 없음.
- DB 없음: Job 상태는 인메모리, 서버 재시작 시 소실.
- 단일 Uvicorn 워커 전제.
- v1은 외부 네트워크를 사용하지 않는다.
- HEIC/AVIF는 v1 지원 대상이 아니다.
- 텍스트 추출은 OCR이 아닌 PDF 텍스트 레이어만 대상이다.

## 4. 범위 제외 (Out of Scope)

- 클라우드 저장/공유, 계정/권한, 다중 사용자
- 이미지 편집(자르기/회전/보정)
- PDF 병합/분할/압축/암호화
- OCR
- HEIC/AVIF
- 변환 결과의 서버 영구 보관
