# PRD.md — 제품 요구사항 문서

## 1. 배경과 문제

사진(jpg/png 등)을 PDF로 묶어야 하는 작업은 흔하지만, 500장 이상을 한 번에 처리할 때 기존 온라인 서비스는 다음 문제가 있다.

- 업로드 용량/개수 제한과 유료 결제 유도
- 개인 사진을 외부 서버로 보내야 하는 프라이버시 부담
- 대량 처리 시 속도 저하와 진행 상황 확인 어려움

또한 만들어진 PDF나 기존 PDF에서 **텍스트만 뽑아 확인/재사용**하고 싶은 수요가 있다. 장기적으로는 추출 텍스트를 **무료 LLM API로 요약**해 읽기 부담을 줄이고자 한다.

## 2. 제품 목표

| 목표 | 설명 |
|---|---|
| G-1 | 로컬에서 500장 이상 이미지를 한 번에 PDF로 변환 |
| G-2 | 변환 순서를 사용자가 통제하고 진행률을 확인 |
| G-3 | PDF 텍스트 레이어를 추출해 복사/저장 |
| G-4 | (v2) 무료 LLM API로 텍스트 요약 |
| G-5 | 외부 전송 없이 개인정보를 로컬에 유지 |

**비목표**: 클라우드 동기화, 협업, 모바일 앱, 이미지 편집, OCR.

## 3. 대상 사용자

- **개인 사용자**: 여행/행사 사진, 스캔 문서를 PDF로 정리하는 사람
- **소규모 사무 사용자**: 영수증/계약서 사진을 문서로 묶는 사람
- 공통: 대량 파일을 외부에 올리기 꺼리는 사용자, 무료 도구를 원하는 사용자

## 4. 핵심 사용자 시나리오

### 시나리오 A — 사진 500장을 PDF로

1. 사용자가 앱을 로컬에서 실행한다.
2. 이미지 500장을 드래그앤드롭한다.
3. 목록에서 순서를 확인하고 일부를 삭제/이동한다.
4. 변환을 시작하고 진행률(예: 237/500)을 본다.
5. 완료 후 PDF를 다운로드한다.
6. PDF를 열어 페이지 수와 순서를 확인한다.

### 시나리오 B — PDF에서 텍스트 추출

1. 사용자가 PDF를 업로드한다.
2. 페이지별 텍스트와 전체 텍스트를 확인한다.
3. 전체 텍스트를 복사하거나 `.txt`로 저장한다.
4. 텍스트 레이어가 없으면 "추출할 텍스트가 없습니다" 안내를 본다.

### 시나리오 C — (v2) 텍스트 요약

1. 추출된 텍스트에 대해 "요약"을 누른다.
2. Gemini 또는 NVIDIA NIM으로 요약된 결과를 확인한다.
3. API 키가 없으면 설정 안내를 본다.

## 5. 범위

### v1 (이번 릴리스)

- 이미지 일괄 업로드/정렬/삭제
- A4 자동 방향 PDF 생성
- 변환 진행률과 다운로드
- PDF 텍스트 레이어 추출/복사/저장
- 입력 검증, 용량/개수 제한, 임시 파일 정리
- 로컬 전용 실행

### v2 (다음)

- Gemini/NVIDIA NIM 기반 요약
- provider 선택 및 키 미설정 시 안내

### 제외

- OCR, HEIC/AVIF, PDF 병합/분할/압축, 계정/공유, 서버 영구 저장

## 6. 사용자 경험 (화면)

```
┌─────────────────────────────────────────────┐
│ Local PDF                                   │
│ [이미지 → PDF] [PDF 텍스트] [요약(v2)]      │
├─────────────────────────────────────────────┤
│  이미지를 끌어다 놓으세요 (최대 1,000장)    │
│  ┌───────────────────────────────────────┐  │
│  │  [썸네일] 001.jpg        ↑ ↓  삭제    │  │
│  │  [썸네일] 002.jpg        ↑ ↓  삭제    │  │
│  │  ...                                  │  │
│  └───────────────────────────────────────┘  │
│  총 500장 · 예상 페이지 500                 │
│  [변환 시작]                                │
│  진행률 ███████░░░ 237/500                  │
│  [PDF 다운로드]                             │
└─────────────────────────────────────────────┘
```

UX 원칙:
- 업로드/변환/오류 상태를 항상 텍스트로 명시한다.
- 파괴적 동작(목록 비우기)은 확인을 받는다.
- 진행률과 처리 수를 함께 보여준다.
- 오류는 원인과 다음 행동을 한국어로 안내한다.

## 8. 릴리스 기준 (Definition of Done)

- 500장 수동 변환 스모크 통과
